# 分享面板与导出样式双轨独立

状态：已接受（v1.2.0）。决策方：#13 spec。

面板与产物是两个视觉表面，决定让它们各自持有一套样式而不共用：分享面板的样式绑宿主语义令牌、随宿主主题实时变化；导出样式（嵌入导出产物内部的视觉语言）在导出时把当前主题解析成具体色值，内嵌进产物。这个分离不是重复实现，而是两个表面的存续环境不同——面板活在宿主里，产物活在本机之外。

## 为什么必须分轨

- 面板依赖宿主运行时：它的颜色只有在宿主加载它时才生效，宿主换主题它跟着换（ADR-0001）。这套机制的前提是宿主变量此刻存在。
- 导出产物（长图 PNG、HTML、Markdown、JSON、PDF）必须离线自足：产物被发到浏览器、邮件、其他机器上打开时，宿主根本不在场，`--ui-*` 与 `--dt-*` 都不存在。产物里的样式只能在导出那一刻固化成具体色值，写进产物自身。
- 反向依赖会同时破坏两端：若产物沿用面板的变量引用，产物离开宿主即失去配色；若面板改用固化色值，宿主换主题面板就不再跟随。所以两轨各自绑定各自的来源，中间只在导出时做一次「宿主计算样式 → 具体色值」的单向解析。
- 分发形态是这条边界成立的前提：宿主加载器强制运行时插件单文件，只允许 import `@hermes/plugin-sdk` 与 react（报错文案：*runtime plugins may only import @hermes/plugin-sdk and react*）。没有共享样式表、没有主题包、没有跨表面复用的通道。

## 快照探针（snapshotTheme）只做变量名修正，机制不变

v1.1.8 的导出探针探测 `--background`（存在）与 `--card` / `--border` / `--accent` / `--muted-foreground` / `--muted`（均不存在），除页背景与文字外全部落到硬编码回退——所谓「跟随宿主主题」实际永远输出浅色回退。本次修正只把探测目标换成宿主真实存在的 `--dt-*`（`--dt-background`、`--dt-foreground`、`--dt-card`、`--dt-border`、`--dt-accent`、`--dt-muted-foreground`、`--dt-muted`）。探针本身的机制保持原样：造隐藏元素、用内联 `var()` 让浏览器把令牌链解析成计算后的 rgba、再固化成具体色值写进导出样式；固定调色板、语法高亮配色、分页与拼页管线一律不动。

## 后果

- 修探针的失败模式不会顺带修好面板，反之亦然：面板的失效样式与产物的失效色值是同一根因（引用了不存在的宿主变量），但两套代码、两处验证，改一边对另一边没有效果。测试因此也是分开的——面板侧看真实渲染，产物侧看内嵌样式表的不变量断言。
- 产物观感与宿主主题只保证「导出那一刻」一致：宿主事后改主题不会追溯改变已导出的产物。这是刻意的，不要把它当 bug 去补同步机制。
- 分享面板的样式与导出样式各自演进不会互相牵连；要跨端保持一致的观感（例如气泡、引用条、工具 chip），需要显式地在两边分别改，不存在一处改两处生效的通道。
